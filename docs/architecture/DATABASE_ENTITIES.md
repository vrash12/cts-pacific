# Planned Database Entities

This document defines the intended PostgreSQL model before Drizzle implementation. Table definitions will be introduced with the feature that owns them so constraints, indexes, RLS policies, and tests are reviewed together.

## Global conventions

- UUID primary keys generated by PostgreSQL
- `created_at` and `updated_at` timestamps with time zone
- Explicit foreign keys and deletion behavior
- Lowercase stable slugs with unique constraints where applicable
- Integer minor units or fixed-precision numeric columns for money; never floating point
- Case-normalized email fields where search or uniqueness requires it
- Enums or checked text values for bounded workflow states
- Minimal storage of personal information and documented retention rules

## Content and services

### `service_categories`

Fields: id, name, slug, description, display order, active state, timestamps.

Constraints: unique slug; non-negative display order.

### `services`

Fields: id, category id, name, slug, summary, technical overview, capabilities, applications, process content, SEO fields, featured-image reference, display order, published state, timestamps.

Constraints: category foreign key; unique slug; non-negative display order.

### `industries`

Fields: id, name, slug, summary, content, display order, published state, timestamps.

Constraints: unique slug; non-negative display order.

## Projects

### `projects`

Fields: id, title, slug, location, sector/industry id, status, summary, challenge, approach, execution, result, featured media id, published state, published timestamp, timestamps.

Constraints: unique slug; optional industry foreign key; published records must satisfy content-readiness rules in application logic.

### `project_services`

Fields: project id, service id, display order, timestamps.

Constraints: unique project/service pair; foreign keys to projects and services; non-negative display order.

### `project_media`

Fields: id, project id, storage path, media type, alt text, caption, width, height, display order, timestamps.

Constraints: project foreign key; unique storage path; positive dimensions when present; required alt text for published informative images.

## Leads

### `contact_submissions`

Fields: id, name, company, email, phone, subject, message, source page, consent metadata, status, assigned admin id, timestamps.

Constraints: bounded status; admin assignment foreign key; server-normalized contact data.

### `quote_requests`

Fields: id, reference number, project location, project type, target timeline, description, contact name, company, email, phone, status, consent metadata, timestamps.

Constraints: unique human-safe reference number; bounded project type and status; description and contact validation.

### `quote_request_services`

Fields: quote request id, service id or approved intake option, timestamps.

Constraints: unique request/service pair; quote foreign key; service foreign key when a catalog service is selected.

## Administration

### `admin_profiles`

Fields: id matching the Supabase Auth user id, role, display name, active state, last-login timestamp, timestamps.

Roles: `SUPER_ADMIN`, `ADMIN`, `CONTENT_EDITOR`, `ORDER_MANAGER`.

Authorization must be enforced in server code and RLS, not inferred from the visible interface.

### `audit_logs`

Fields: id, actor user id, action, entity type, entity id, request correlation id, redacted metadata JSON, approved request metadata, created timestamp.

Constraints: actor foreign key when available; indexes for entity and timestamp lookup; no secrets or unnecessary personal data in metadata.

### `settings`

Fields: id, key, typed value JSON, description, updated-by admin id, timestamps.

Constraints: unique key; protected updates; secrets must not be stored here.

## Future commerce

### `product_categories`

Fields: id, parent id, name, slug, description, display order, active state, timestamps.

Constraints: unique slug; optional self-referencing parent; cycle prevention in application logic.

### `products`

Fields: id, category id, name, slug, description, active state, published timestamp, timestamps.

Constraints: unique slug; category foreign key.

### `product_variants`

Fields: id, product id, SKU, name, price minor units, currency, inventory policy, active state, timestamps.

Constraints: unique SKU; non-negative price; ISO currency validation; product foreign key.

### `product_images`

Fields: id, product id, storage path, alt text, display order, dimensions, timestamps.

Constraints: product foreign key; unique storage path; non-negative display order.

### `customers`

Fields: id, optional Supabase Auth user id, normalized email, name, phone, timestamps.

Constraints: optional auth-user uniqueness; explicit guest-checkout email policy.

### `addresses`

Fields: id, customer id, type, recipient, lines, locality, region, postal code, country code, timestamps.

Constraints: customer foreign key; ISO country code; no unnecessary address retention.

### `carts`

Fields: id, optional customer id, anonymous session-token hash, status, currency, expiration timestamp, timestamps.

Constraints: bounded status; never store a raw bearer-equivalent cart token.

### `cart_items`

Fields: id, cart id, variant id, quantity, timestamps.

Constraints: unique cart/variant pair; positive quantity; server loads authoritative variant price when calculating totals.

### `orders`

Fields: id, order number, customer id, email snapshot, status, currency, subtotal, tax, shipping, total, address snapshots, timestamps.

Constraints: unique order number; non-negative monetary values; total-reconciliation check; bounded status transitions.

### `order_items`

Fields: id, order id, variant id, SKU/name snapshots, unit price, quantity, line total, timestamps.

Constraints: positive quantity; non-negative prices; line-total consistency; product information is snapshotted for historical accuracy.

### `payments`

Fields: id, order id, provider, provider order id, provider capture id, amount, currency, status, idempotency key, timestamps.

Constraints: unique provider identifiers where present; unique idempotency key; order foreign key; amount and currency reconciliation.

### `payment_events`

Fields: id, payment id, provider event id, event type, verification state, redacted payload JSON, processed timestamp, created timestamp.

Constraints: unique provider event id; duplicate-webhook protection; payload retention policy.

## Knowledge and chatbot

### `knowledge_articles`

Fields: id, title, slug, approved content, service id, published state, approved-by admin id, approved timestamp, timestamps.

Constraints: unique slug; optional service foreign key; only approved and published content may be used for customer answers.

### `chat_sessions`

Fields: id, anonymous token hash or optional customer id, status, consent metadata, started timestamp, ended timestamp, timestamps.

Constraints: bounded state; documented retention and deletion behavior.

### `chat_messages`

Fields: id, session id, role, content, provider metadata stripped of secrets, created timestamp.

Constraints: session foreign key; bounded role; message-length limits.

### `chat_leads`

Fields: id, session id, name, company, email, phone, project summary, status, quote request id, timestamps.

Constraints: session foreign key; optional quote foreign key; consent required before lead creation.
